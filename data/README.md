# data/

| 경로 | 내용 | 저장소 커밋 |
|---|---|---|
| `history/YYYY-MM-DD.json` | 그날 수집한 회차별 예측값(모델·지표별 극값), 계산 결과(가능성·등급), 실제 특보·예비특보 기록 | **예** — 지우지 않습니다 (2단계 분석용) |
| `accuracy.json` | 이력으로 집계한 적중률(사전 포착률·오경보율) | 예 |
| `backtest.json` | 과거 검증 — 지난 예보로 가능성을 다시 계산해 실제 특보와 맞춰 본 결과(`teukbo.backtest`, 매주 갱신) | 예 |
| `rail/days/YYYY-MM-DD.json` | 그날 열차별 종착 지연과 지나간 구간의 특보(코레일 공식 운행 기록 기준), 노선·특보별 집계 — 웹에는 `data/rail-days/` 로 배포(분석 화면의 ‘그날의 열차’) | **예** — 지우지 않습니다 |
| `rail/events/YYYY-MM.json` | 특보 발표·해제 이력 보관분(공식 조회가 약 60일까지만 되므로 받아 둠) | 예 |
| `rail/summary.json` | 열차 지연 누적 통계 — 웹에는 `data/rail.json` 으로 배포 | 예 |
| `rail/cube.json` | 날짜 × 노선 × 열차 종류 × 지나간 특보 단위 집계(분석 화면이 조건을 바꿔 가며 다시 셈). 특보 구간을 지난 열차에는 ‘같은 열차의 평소 대비’ 합도 싣는다 — 웹에는 `data/rail-cube.json` 으로 배포. `rail/days/` 로부터 언제든 다시 만들 수 있음 | 예 |
| `obs/YYYY-MM.json` | 기상청 관측소(ASOS)의 하루 단위 관측값 — 최저·최고기온, 강수량, 신적설, 풍속, 습도(`teukbo.obs`, 날마다 이어 받음). 지역별 기록의 ‘그날의 날씨’ | **예** — 지우지 않습니다 |
| `latest.json` | 웹이 처음 읽는 최신 결과(전체 지역 요약) | 아니오 — 배포 전용 |
| `records/<지역>.json` | 지역별 기록 — 특보가 발효된 날과 그날의 관측값(`teukbo.records`). `rail/events/` 와 `obs/` 로부터 사이트를 조립할 때마다 다시 만든다 | 아니오 — 배포 전용 |
| `hourly/YYYY-MM-DD/HH.json` | 기상청 초단기실황의 정시 값 — 지역 격자(225곳)마다 기온·습도·풍속·1시간 강수량·강수형태(`teukbo.hourly`, 3시간마다 이어 받음). 지역별 기록의 ‘시간대별 체감온도·날씨’ | **예** — 지우지 않습니다 |
| `hourly/calls.json` | 오늘 시간별 실황을 부른 횟수(하루 상한을 넘기지 않으려고 센다) | 예 |
| `hours/<지역>/<연-월>.json` | 지역별 시간대 값 한 달치(체감온도 포함) — 달력에서 날짜를 누르면 읽는다(`teukbo.records`). `hourly/` 로부터 사이트를 조립할 때마다 다시 만든다 | 아니오 — 배포 전용 |
| `work_rules.json` | 폭염·한파 작업 기준 — `config/work_rules.json` 을 그대로 복사 | 아니오 — 배포 전용 |
| `warnings.json` | 전국 특보·예비특보(특보구역 코드 단위) — 철도 특보 지도가 읽음 | 아니오 — 배포 전용 |
| `detail/<지역>.json` | 지역별 모델 비교 표·그래프 자료 | 아니오 — 배포 전용 |

실시간 자료(`live.json`)는 이 폴더가 아니라 저장소의 **`live` 브랜치**에 최신 한 벌만 올라갑니다(5분마다 덮어씀, 기록은 쌓지 않음).
같은 브랜치의 `state.json` 은 다음 실행이 이어 쓰는 상태(레이더 최근 1시간의 선로 표본점 값)이며 화면은 읽지 않습니다.
형식은 `teukbo/live.py` 맨 위 설명을 보세요.

`latest.json` 과 `detail/` 은 3시간마다 통째로 바뀌는 파일이라 커밋하면 저장소가 빠르게 커집니다.
그래서 GitHub Pages 에만 올리고(`.gitignore` 처리) 저장소에는 누적 가치가 있는 이력만 남깁니다.
배포된 최신 파일은 `https://<계정>.github.io/<저장소>/data/latest.json` 에서 볼 수 있습니다.

## history 파일 형식

```jsonc
{
  "schema": 1,
  "date": "2026-11-12",
  "runs": [
    {
      "t": "2026-11-12T21:25+09:00",            // 수집 시각(KST)
      "ok": {"open_meteo": true, "kma_forecast": true, "kma_warnings": true},
      "models": ["kma_dfs", "ecmwf_ifs025", "…"], // regions[].h[].r 의 순서
      "ind": ["apparent_max", "gust", "…"],        // regions[].x[모델] 의 순서
      "thresholds": "2026-06-30",                  // 적용한 기준 판
      "regions": {
        "suncheon": {
          "x": {"ecmwf_ifs025": [[12.3, 31], null, "…"]},   // 지표별 [예측 범위 내 극값, 선행시간(h)]
          "h": {"heavy_rain_advisory": {"p": 56, "mg": "caution", "g": "high", "r": [0.9, 1.25, "…"], "w": ["시작", "끝"]}},
          "a": [{"k": "heavy_rain", "l": "advisory", "n": "호우주의보", "f": "발효 시각"}],  // 발효 중 특보
          "pre": [{"k": "heavy_rain", "l": null, "n": "호우", "e": "13일 오전(06시~12시)"}]  // 예비특보
        }
      }
    }
  ]
}
```

- `h` 에는 가능성이 0%가 아닌 특보만 들어갑니다(없으면 0%·낮음).
- `mg` 는 예측값만으로 계산한 등급, `g` 는 기상청 발표(예비특보·특보)를 반영한 최종 등급입니다.
- `a`·`pre` 키 자체가 없으면 그 회차에 특보 조회가 실패한 것입니다(‘특보 없음’과 구별).
- `nat` 은 그 회차의 전국 특보입니다: `{"a": {"호우주의보": ["L1051200", …]}, "p": {"호우": […]}}` (특보구역 코드, `a` 발효 중 · `p` 예비특보).

## obs 파일 형식

```jsonc
{
  "schema": 1,
  "month": "2026-11",
  "vars": ["rain", "rain_1h_max", "wind_max", "gust_max", "temp_min", "temp_max", "rh_avg", "snow_new", "rh_min", "wind_avg"],  // 값의 순서
  "stations": {
    "258": {"name": "보성군", "days": {"2026-11-24": [0.0, null, 5.5, 9.9, -3.2, 6.4, 55.0, null, 31.0, 2.1]}}   // 지점번호 → 날짜 → 값
  }
}
```

- 지점은 `config/asos_stations.json` 의 것, 값은 공공데이터포털 「기상청_지상(종관, ASOS) 일자료 조회서비스」의 일강수량(mm)·1시간 최다강수량·최대 풍속·최대 순간풍속(m/s)·최저·최고기온(℃)·평균 습도(%)·일 최심신적설(cm)·최소 습도·평균 풍속입니다.
- 전날 값은 오전 11시 뒤에 올라옵니다. 그 뒤 첫 수집 회차가 지점마다 ‘저장된 마지막 날의 다음 날 ~ 어제’를 한 번에 받습니다(받을 날이 없으면 호출하지 않음).
- 강수량·신적설의 `null` 은 ‘그날 기록되지 않음(없음)’입니다. 달이 바뀌어 변수가 늘어도 `vars` 로 맞춰 읽습니다.

## records 파일 형식 (배포 전용)

```jsonc
{
  "schema": 1, "id": "beolgyo", "name": "보성(벌교)",
  "station": {"stn": "258", "name": "보성군", "km": 14.7},   // 하루 값을 가져온 관측소와 직선거리. 40km 안에 없으면 null
  "from": "2026-09-15", "to": "2026-11-26",                  // 특보 발표 이력이 있는 기간(없으면 null)
  "obs_to": "2026-11-25",                                     // 관측소 일자료가 있는 마지막 날(없으면 null)
  "hours": {"from": "2026-11-25", "to": "2026-11-26"},        // 시간별 값이 있는 첫날~마지막 날(없으면 null)
  "vars": ["temp_min", "temp_max", "rain", "snow_new", "wind_max", "gust_max"],
  "days": {
    "2026-11-26": {
      "o": [3.1, 9.8, 2.5, 0.0, 11.3, 21.4],                   // vars 순서의 관측소 일자료. 그날 것이 없으면 키가 없다
      "w": [["strong_wind", "advisory", "2026-11-26T04:00+09:00", "2026-11-26T15:00+09:00"]],   // 그날 발효 중이던 특보. 없으면 키가 없다
      "h": 24,                                                 // 시간별 값이 있는 시각 수. 없으면 키가 없다
      "f": [-2.1, 6, 9.8, 14]                                  // 체감온도 [최저, 그 시, 최고, 그 시] — 체감온도가 있는 시각이 20(feel_min_hours) 이상일 때만
    }
  }
}
```

- `w` 는 그날(한국 시각 0~24시) 한순간이라도 발효 중이던 특보 `[종류, 단계, 발효 시각, 해제 시각]` 입니다. 아직 해제되지 않았으면 해제 시각이 `null`. 이 서비스가 다루는 종류(`thresholds.json` 의 `types`)만 싣습니다.
- 관측소는 그 지역 안에 있는 지점을 먼저, 없으면 가장 가까운 지점을 씁니다. **그 지역 한가운데의 값이 아니라 관측소의 값**입니다.
- `rain`·`snow_new` 는 그날 관측이 있는데 값이 비어 있으면 0 으로 싣습니다.
- 그날의 체감온도 최저·최고(`f`)는 **시간별 실황으로만** 구합니다. 하루 값(최저기온·평균풍속)으로 어림하던 값은 싣지 않습니다 — 가장 추운 새벽에는 바람이 약한데 하루 평균 풍속을 넣으면 실제보다 낮게 나왔습니다(보성군 2026-11-24: 어림값 -4.1℃, 정시별 실제 최저 -1.5℃). 체감온도가 있는 시각이 모자란 날(20시각 미만 — 수집 첫날, 오늘, 수집이 멈췄던 날)은 `f` 가 없습니다.
- 특보 이력을 받기 시작하기 전의 날은 싣지 않습니다(‘특보 없음’과 구별되지 않으므로). 최근 400일(`settings.json` 의 `records.keep_days`)만 싣습니다.

## hourly 파일 형식

```jsonc
// data/hourly/2026-11-26/14.json — 기준시각(한국 시각)의 날짜·시
{
  "schema": 1, "t": "2026-11-26T14:00+09:00",
  "vars": ["temp", "rh", "wind", "rain", "pty"],              // 기온 ℃ · 습도 % · 풍속 m/s · 1시간 강수량 mm · 강수형태 코드
  "grids": {"67,68": [0.8, 81, 2.8, 0.0, 0]},                 // "nx,ny"(기상청 5km 격자) → vars 순서의 값. 없는 값은 null
  "missing": ["61,128"], "tries": 1                           // 못 받은 격자가 있을 때만(다 받았으면 두 키가 없다)
}
```

- 기상청 **초단기실황**(공공데이터포털 단기예보 조회서비스의 `getUltraSrtNcst`)입니다. 기상청 설명으로는 5km 격자마다 짝지어 둔 대표 방재기상관측(AWS) 지점의 관측값이며, 응답에는 어느 지점인지가 들어 있지 않습니다. 하늘 상태는 이 자료에 없습니다.
- **최근 23시간까지만 조회됩니다**(2026-11-26 실제 응답으로 확인: 24시간 전부터는 “최근 1일 간의 자료만 제공합니다”). 수집이 하루 넘게 멈추면 그 사이의 시각은 다시 받을 수 없어 빈 채로 남습니다.
- 다 받은 파일은 다시 쓰지 않습니다. 못 받은 격자가 남은 파일만 다음 실행들이 두 번(`hourly.refill_tries`)까지 다시 채웁니다.
- 강수형태 코드: 0 없음 · 1 비 · 2 비/눈 · 3 눈 · 4 소나기 · 5 빗방울 · 6 빗방울눈날림 · 7 눈날림.
- 하루 호출 수는 약 5,400회(225격자 × 24시각)입니다. `hourly.daily_call_cap`(기본 7,000)을 넘기지 않습니다 — 같은 서비스의 하루 한도(개발계정 10,000건)를 단기예보 수집과 나눠 쓸 수도 있어서입니다.

## hours 파일 형식 (배포 전용)

```jsonc
// data/hours/beolgyo/2026-11.json
{
  "schema": 1, "id": "beolgyo", "name": "보성(벌교)", "month": "2026-11", "grid": [67, 68],
  "source": "기상청 초단기실황(이 지역 격자의 대표 관측지점 정시 값). 체감온도는 기상청 식으로 계산한 값",
  "vars": ["temp", "feel", "rain", "wind", "rh", "pty"],
  "feel_stat": "min",                                          // 이 달에 눈여겨볼 쪽: 겨울철 식을 쓰는 달은 min, 여름철 식을 쓰는 달은 max
  "days": {"2026-11-26": {"h": [0, 1, 2], "v": [[0.8, -2.1, 0.0, 2.8, 81, 0], [0.5, 0.5, 0.0, 1.2, 84, 0], [0.1, -1.9, 0.0, 1.6, 86, 0]]}}
}
```

- `h` 는 그 날 값이 있는 시(0~23), `v[i]` 는 `h[i]` 시의 값(vars 순서)입니다. 값이 없는 시각·날은 싣지 않습니다.
- 체감온도(`feel`)는 조립할 때 시각마다 기상청 식으로 **계산한 값**입니다: 5~9월(`feel.summer_months`)은 여름철 식(기온·습도), 그 밖의 달은 겨울철 식(기온·풍속 — 기온 10℃ 이하·풍속 4.8km/h 초과일 때만, 아니면 기온 그대로). 재료가 없으면 `null`.
- 겨울철 식의 풍속 경계는 기상청 설명문(“1.3m/s 이상”)이 아니라 **기상청이 실제로 표출하는 값의 경계(4.8km/h 초과)** 를 따릅니다 — 날씨누리 정시 관측 표 397행과 모두 일치했습니다(설명문대로면 풍속 1.3m/s 인 3행이 어긋남).
- 초단기실황의 풍속이 몇 분 평균인지는 기상청 문서에 없습니다. 기상청이 표출하는 체감온도(10분 평균 풍속 기준)와 조금 다를 수 있습니다.

## rail/days 파일 형식

```jsonc
{
  "schema": 1,
  "date": "2026-11-11",
  "final": true,                       // false = 그날이 끝난 지 하루가 안 되어 다시 확인할 파일
  "counts": {"planned": 863, "recorded": 860, "measured": 858, "no_record": 3, "no_terminus": 2},
  "all": {"n": 858, "mean": 2.4, "median": 1.0, "max": 47, "late5": 96, "late10": 31, "late20": 8},  // 종착 지연(분)
  "clear": {…},                       // 특보 구간을 지나지 않은 열차
  "by_warning": {"호우": {…}},         // 지나간 구간에 있던 특보 종류별
  "by_line": {"전라선": {…}}, "by_class": {"KTX": {…}},
  "fields": ["trn_no", "line", "class", "origin", "dest", "plan_dep", "plan_arr", "dep_delay", "arr_delay", "warnings"],
  "trains": [["00501", "전라선", "KTX", "용산", "여수엑스포", "05:10", "08:13", 0, 3, ["호우주의보"]]]
}
```

- 지연은 `실제 − 계획`(분)입니다(일찍 도착하면 음수로 남기고, 통계에서는 0으로 셉니다). 역별 계획 시각은 공개되지 않아 시발역 출발·종착역 도착만 계산합니다.
- `warnings` 는 열차가 정차한 역의 특보구역에, 그 역을 지난 시각에 발효 중이던 특보(같은 종류면 가장 높은 단계)입니다.
